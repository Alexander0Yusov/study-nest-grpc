# Рабочая инструкция агента

## Роли

- Пользователь определяет цели, пишет основной учебный код руками и утверждает изменения.
- Архитектурный ChatGPT анализирует, объясняет теорию, проектирует решение, формирует задачи и проверяет отчёты.
- Агент в коде выполняет исследование, проверку и только явно делегированные изменения.
- Агент не принимает самостоятельно архитектурные и продуктовые решения.

## Режимы работы

Если режим явно не указан, задача считается `DISCOVERY ONLY`.

- `DISCOVERY ONLY`: только чтение, поиск и отчёт; изменения запрещены.
- `IMPLEMENTATION APPROVED`: разрешены только перечисленные файлы и scope; расширять задачу запрещено.

## Учебный принцип

- Основной прикладной код пользователь пишет либо переносит руками; агент не реализует фичу целиком автоматически.
- До кодирования агент объясняет, что создаётся, зачем и как это работает.
- До каждой темы изучается точечный корпоративный аналог. После реализации агент может выполнить read-only review и разрешённые проверки.
- Механическая генерация и делегирование возможны только после отдельного одобрения.

## Ориентиры

- [PLAN.md](PLAN.md) определяет архитектуру и последовательность обучения.
- [TASKS.md](TASKS.md) содержит только текущую задачу.
- [Course checklist](docs/course-checklist.md) показывает покрытие тем курсов.
- [Learning log](docs/learning-log.md) хранит фактическую хронологию.
- Корпоративные сервисы задают ориентир рабочего стиля, но legacy не копируется автоматически. При конфликте агент останавливается и сообщает о нём.

## Минимальные инженерные правила

- KISS и YAGNI; маленькие проверяемые изменения без несвязанного рефакторинга.
- Не добавлять зависимости без одобрения; generated-файлы вручную не изменять.
- TypeScript strict и осмысленный naming.
- Бизнес-логика не размещается в controllers.
- Не оставлять dead code и временные `console.log`.
- Не менять архитектуру и контракты без одобрения.

## Синхронизация обучения

Каждая задача указывает связанные IDs из [course-checklist.md](docs/course-checklist.md). Практическая тема завершена только когда теория объяснена, код написан, результат проверен, добавлен кодовый пин, а checklist и learning log обновлены.

## Безопасность и Git

Корпоративные репозитории строго read-only; секреты не читать и не коммитить. `commit`, `push` и `merge` возможны только по отдельному разрешению. После изменения показать проверки и `git status`.
